Living Textbook · Design report

How a chapter becomes
a living lesson

Three lesson flows, how we split a chapter into episodes, and our automation pipeline
In one minute
  1. Three lesson flows. Every concept is taught with one of three simple patterns: Story, Challenge or Wonder. Each one hooks the class with a real Indian example, connects it to the concept, explains it from the NCERT textbook, then checks understanding.
  2. Chapters become episodes. A chapter is split into short episodes of 1–2 concepts, each fitting one class period, like a web series: Opener → Episodes → Finale.
  3. One automated pipeline, one app. We give the system a chapter PDF; it plans, scripts, voices, draws, animates and packages the lesson. The player app never changes. Only the chapter content does.

Who it is for

StudentsNCERT Classes 5–10. Pilot subjects: Science, Social Science, Maths
SettingThe teacher projects the lesson to the whole class. The class votes by show of hands; the teacher taps the majority answer.
ContextRooted in rural India (Karnataka, Maharashtra, Gujarat first): local crops, food, weather, markets, festivals
LanguageEnglish first. Narration-based, so other languages are added later by re-recording the voice only
Visual styleInspired by the NCERT illustrations, made richer. Indian characters appear on screen but don't speak; a narrator tells the story.

Why we changed the old flow

Old flow (Predict → Observe → Explain → Check)New approach
3 questions asked before students saw anythingHook first: a story, problem or surprising sight, then one question
Foreign examples (willow tree, lab beaker)Indian, rural examples the child has already seen
Not mapped to the NCERT chapterFollows the NCERT concepts and activities one to one
20 personalised video paths for one studentWhole-class vote; at most 2–4 short replies per question
Built for one topic onlyWorks for any subject and any chapter

1The three lesson flows

All three follow the same teaching idea: create interest → connect to the concept → explain from the textbook → check. What changes is where the interest comes from.

Flow 1: Story

Interest from a character
StoryReal-life scene with an Indian child; ends on a question
→
Vote"What do you think?" Class votes
→
ExplainTextbook concept, 60–90 s
→
RevealWhose guess was right, and why
→
Check1–2 quick MCQs
Best for: every subject; strongest in Social Science.
Example (Social): Zoya's father, a fisherman in Kutch, wants to sail. The barometer reads 996 mb. Sail or stay? → air pressure explained.

Flow 2: Challenge

Interest from a problem
ChallengeA real job: "Help the shopkeeper / farmer…"
→
TryClass attempts it with what they know
→
Stuck"We can't decide without knowing ___"
→
LearnConcept arrives as the missing tool
→
SolveBack to the challenge, now solved
→
New challengeSame idea, new situation (MCQ)
Best for: Maths and practical Social topics. Being stuck first makes the explanation matter (research calls this "productive failure").
Example (Maths): Pooja keeps score on sports day. Priya jumped 3.5 m, Anu 3.45 m. Who won? → comparing decimals.

Flow 3: Wonder

Interest from a surprise
WonderA surprising sight, 10–15 s, no narration
→
QuestionClass picks what they want to find out
→
InvestigateThe NCERT activity: live, simulated or on video
→
ExplainAnswers the class's question
→
ApplyMCQ + "spot it near your home"
Best for: Science and other activity-heavy chapters. It matches the NCERT approach of asking questions first.
Example (Science): Grass under a lifted stone is yellow in a green field. Why? → test with 3 pots → plants need light to make food.

2Dividing a chapter into episodes

A chapter has many concepts, too many for one sitting. We split it like a web series: an opener that sets up the story world, short episodes that each fit one class period, and a finale.

Structure of a chapter

CHAPTERe.g. Science Ch 10 "Life Processes in Plants" · 7 concepts

↓

Inside every episode

Recap (15 s)"Last time…" + 1 recall question
Concept loop · repeated for 1–2 concepts · uses the chosen flow
HookStory / challenge / wonder
→
VoteClass decides
→
ExplainTextbook concept
→
CheckMCQ
Cliffhanger (10 s)"But the plant in the jar is still weak. What's missing? Next time…"

The recap helps students remember: recalling last lesson's idea is one of the strongest ways to make learning stick. The cliffhanger gives the class a reason to come back.

3Our automation flow

From a chapter PDF to a finished classroom lesson. Steps marked orange need a human decision; everything else is automated.

1
UserIntake: upload the NCERT chapter PDF.
2
AutomatedAnalyse: find the subject, concepts, activities, in-text questions, fact boxes and end-of-chapter questions. Size each concept (big / small / fact).
3
AutomatedPlan: split into episodes (1–2 concepts per period); choose a flow per concept (Story / Challenge / Wonder); choose the Indian setting and story world; sort activities into Do-along / Simulator / Mission.
✓
Team reviewCheckpoint: approve the episode plan before anything is produced. Changes here are cheap; changes after rendering are expensive.
4
AutomatedScript: narration lines, vote options (built from misconceptions), MCQs, recap and cliffhanger lines.
5
User picks voiceNarration audio: choose the narrator voice → generate with ElevenLabs → measure each line's length (timing is built around the audio).
6
AutomatedVisuals: style reference → characters, scenes and props → storyboards → still images (vote cards, MCQ images, fact cards).
7
Existing skill filesAnimation → review → edit: EN2 renders from storyboards, cut review, re-time or repair, stitch with narration.
8
AutomatedPackage: write the chapter content file (chapter.json) + media folder → drop into the standard player → ZIP, ready to open offline.

3One app for every chapter

The player app is built once. For each new chapter, in any subject, only the content changes. The app code is never edited.

Reusable simulators, set up from the content file

Simulators are the only interactive parts. To avoid writing new code per chapter, we build a small set of templates and configure them with data:

If an activity doesn't fit any template, it is shown as a short video instead, so no new code is needed per chapter.

What this gives us

New chapterNew chapter.json + media; same app
New subjectSame three flows, same screen types
New languageRe-record narration and translate the text in chapter.json; videos are reused (no on-screen text, no lip-sync)
Offline classroomsThe whole lesson runs from a ZIP: open index.html, no internet needed
